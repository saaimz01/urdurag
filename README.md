# IR Project — Roman Urdu RAG System
# CS4051 Information Retrieval

## Project Overview
A Retrieval-Augmented Generation (RAG) system for Roman Urdu question answering.
Compares a baseline (raw Roman Urdu → LaBSE) against an improved system
(Lex-Var normalization → transliteration → LaBSE).

## Setup

### 1. Install dependencies
```bash
pip install -r requirements.txt
```

### 2. Clone Lex-Var
```bash
git clone https://github.com/abdulrafae/normalization normalization/lexvar_repo
```
Then read the README inside that repo to confirm the correct script name and arguments.
Adjust the `possible_scripts` list in `normalization/normalize.py` if needed.

### 3. Set DeepSeek API key
Get a free key from https://platform.deepseek.com

Windows:
```
set OPENAI_API_KEY=your_key_here
```
Mac/Linux:
```
export OPENAI_API_KEY=your_key_here
```

## Run Order (do this once, in order)

```bash
# Step 1: Put your Urdu article .CSV file in data/articles/
#         Then chunk them into passages
python chunking.py

# Step 2: Build ground truth queries interactively
python build_queries.py

# Step 3: Run Lex-Var normalization + transliteration on queries
python normalization/normalize.py


# Step 4: Embed all chunks and build FAISS index
#         (downloads ~1.8GB LaBSE model on first run)
python embeddings/embed.py

# Step 5: Run retrieval for both baseline and improved systems
python retrieval/retrieve.py

# Step 6: Evaluate and compare both systems
python evaluation/evaluate.py

# Step 7: Interactive demo
python pipeline.py
```

## Key Design Decisions

| Decision | Choice | Why |
|----------|--------|-----|
| Embedding model | LaBSE | Multilingual, handles Urdu + code-switching |
| Vector store | FAISS IndexFlatIP | Exact search, fast enough for <100k chunks |
| Normalization | Lex-Var (Rafae et al.) | Published method, proven on Roman Urdu |
| Transliteration | Rule-based (UrduPhone mapping) | urduhack has no roman_to_urdu; this follows the paper directly |
| Generation | OpenAI-chat | Free tier, understands Urdu + Roman Urdu |
| Chunk size | 200 words, 50 overlap | Balances specificity vs context |

## Evaluation Metrics

| Metric | What it means |
|--------|---------------|
| P@1 | Is the very first result correct? |
| P@3 | Of top 3, fraction that are correct |
| P@5 | Of top 5, fraction that are correct |
| R@1 | Is correct answer in top 1? |
| R@3 | Is correct answer in top 3? |
| R@5 | Is correct answer in top 5? |
| MRR | Mean reciprocal rank — rewards finding correct answer higher up |

## Common Issues

**"Module not found" errors**
Run all scripts from the project root directory (`ir_project/`), not from inside subdirectories.

**LaBSE download is slow**
Normal — it's ~1.8GB. Only happens once. After that it's cached.

**Lex-Var script not found**
After cloning, run `ls normalization/lexvar_repo/` and check the actual script names.
Update `possible_scripts` in `normalization/normalize.py` accordingly.

**OPENAI_API_KEY not set**
Pipeline runs in retrieval-only mode — all retrieval and evaluation still works,
just no answer generation.

**My articles are in JSON not TXT**
In `chunking.py`, comment out `load_from_txt_folder()` and
uncomment `load_from_json()`. Adjust the JSON field names to match your format.
